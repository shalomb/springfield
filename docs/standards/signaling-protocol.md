# Springfield Signaling Protocol

**Status:** Draft
**Applies to:** All Agents and the Springfield Orchestrator

---

## 1. The Sentinel Concept

The **Sentinel** is a cryptographic nonce (UUIDv4) generated by the Orchestrator at the moment an agent session is spawned. It serves two purposes:
1.  **Authorization:** Proves the agent attempting to transition state is the one assigned to the task.
2.  **Termination:** Acts as the "Kill Switch" for the agent loop.

The Sentinel is injected into the agent's System Prompt via the `{{.Sentinel}}` template variable. It is known *only* to the Orchestrator and the running Agent instance.

---

## 2. The `springfield signal` Command

Agents terminate their session *exclusively* by executing this command. They do not exit via natural language or `[[FINISH]]` markers.

### Syntax
```bash
springfield signal --sentinel <token> --status <status> [--reason "message"]
```

### Flags
| Flag | Required | Type | Description |
| :--- | :--- | :--- | :--- |
| `--sentinel` | Yes | `string` | The session token received in the prompt. |
| `--status` | Yes | `enum` | The outcome of the session (see below). |
| `--reason` | No | `string` | A brief summary of the result (e.g., "Tests passed", "Plan complete"). |

---

## 3. Allowed Status Transitions

The Orchestrator enforces Role-Based Access Control (RBAC) on status signals.

### 📚 Lisa (Planner)
*   **Context:** Finds `Planned` Epics.
*   **Allowed Signals:**
    *   `complete`: Plan is ready. Transitions Epic to `Ready`. Triggers Worktree provisioning.
    *   `blocked`: Cannot plan (missing info). Transitions Epic to `Blocked`.

### 🤖 Ralph (Builder)
*   **Context:** Wakes up in `feat/epic-{id}` worktree.
*   **Allowed Signals:**
    *   `success`: Implementation complete & tests pass. Transitions Epic to `Implemented`. Triggers Bart.
    *   `blocked`: Technical blocker. Transitions Epic to `Blocked`. Triggers Lisa.

### 🛹 Bart (Reviewer)
*   **Context:** Wakes up in `feat/epic-{id}` worktree (same as Ralph).
*   **Allowed Signals:**
    *   `success`: Verified. Transitions Epic to `Verified`. Triggers Lovejoy.
    *   `failed`: Bugs found. Transitions Epic to `In Progress`. **Triggers Ralph (Correction Loop).**
    *   `blocked`: Architectural failure. Transitions Epic to `Blocked`. Triggers Lisa.

### ⛪ Lovejoy (Releaser)
*   **Context:** Wakes up in `feat/epic-{id}` worktree.
*   **Allowed Signals:**
    *   `released`: Merged & Cleanup done. Transitions Epic to `Done`. Deletes Worktree.

---

## 4. The Correction Loop (Bart → Ralph)

When Bart signals `failed`, the Orchestrator performs a **State Rewind**:

1.  **State:** Epic moves from `Implemented` back to `In Progress`.
2.  **Environment:** The worktree `feat/epic-{id}` is **preserved**. It is NOT deleted.
3.  **Context:** Bart leaves his findings in `FEEDBACK.md` in the worktree root.
4.  **Process:** The Orchestrator kills Bart's process and immediately spawns a new Ralph process in the same directory.
5.  **Ralph's Prompt:** Ralph receives standard instructions + "Check FEEDBACK.md".

This ensures Ralph wakes up exactly where Bart left off, with the context needed to fix the bugs.

## 5. Implementation Details

### The Orchestrator Loop (Daemon)
```go
func (o *Orchestrator) Daemon() {
    for {
        // 1. Poll td for actionable states
        epics := o.TD.Scan()
        
        // 2. Reconcile Process Table
        for _, epic := range epics {
            if !o.HasActiveWorker(epic.ID) {
                o.SpawnWorker(epic)
            }
        }
        
        time.Sleep(1 * time.Second)
    }
}
```
